Detailed Description

This is the base definition of a SCION enabled Node. A SCION_Node models an Autonomous System.

Member Enumeration Documentation

◆ neighbour_relation

enum SCION_Node::neighbour_relation

Different types of links.

In typical BGP-enabled internet topologies, there are peer, and customer links. The Provider type was introduced to model the reverse directionality of a customer link, the core type is found between core-ASes in SCION-topologies.

◆ DoInitializations()

void SCION_Node::DoInitializations ( )

Initializes the latencies_between_interfaces and the as_max_bw fields.

The intra as latencies are estimated by calculating the great circle latencies based on the interface coordinates. Also initializes AS_max_bwd with the highest bandwith found at any border router of this AS.

Iterates over all the beacons and fills the provided structures with the distribution of achieved scores.

Calculates the link-level and as-level path diversity scores and a quality metric (based on the latency and bandwidth coefficients in the beacons and the node) for each beacon. Saves the numeric value and the distribution (frequency of occurrence of a certain score) in the passed maps.

See also
calculate_final_diversity_scores

◆ next_round_valid_beacons_count_per_src_as

std::unordered_map<uint16_t, uint64_t> SCION_Node::next_round_valid_beacons_count_per_src_as

This structure counts how many valid beacons will be known per source AS after the current beaconing period is complete.

It is the sum of the currently valid beacons and the beacons that will be valid in the next beaconing period. This structure is used to decide if an AS would discard the a newly sent beacon or not.
